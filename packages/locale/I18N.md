# 多语言规范 I18N（锁定）

> 实现：`packages/locale/` · `LocaleService` · `useLocale()` · `html[data-locale]` / `lang` / `dir`  
> Agent 记忆：`.cursor/rules/vue3-amg-webui-i18n.mdc`

---

## 1. 目标

按钮文字、页面标题、提示信息、错误信息、表单校验与业务文案 **一律走 key**，禁止在组件/页面/**example 调试壳**硬编码用户可见字符串（品牌专有名词 `AMG-WebUI` 除外；其余 demo 文案也必须有 key）。

硬编码（文案 / hex / 随意 px·rem）视为 **bug**。Cursor：`vue3-amg-webui-no-hardcode.mdc`（alwaysApply）。

**强类型 i18n（已落地）**

- `LocaleKey` / `LocaleMessages` 由 `zh-CN` 生成（`message-schema.ts`，`npm run generate:locale-types` / `extract:i18n`）
- `LocaleService.t` / `useLocale().t` **只接受 `LocaleKey`** — 任意字符串编译失败
- 各语种 `index.ts` 使用 `satisfies LocaleMessages` — **缺 key 编译失败**
- `LocaleKeys` 树 `satisfies LocaleKeyTree` — 叶子必须是合法 `LocaleKey`
- 动态拼接 key 用 `useLocale().tDyn`（运行时 `isLocaleKey` 校验）

**原生 RTL（已落地）**

- `LOCALE_META.*.dir` + `LocaleService.setLocale` 写入 `html[dir]`
- 内置 RTL 语种：`ar-SA`（`dir: rtl`；文案暂以 en-US 为底，可逐步阿语化）
- `LocaleService.setDirection('rtl' | 'ltr' | null)` 强制预览 / 恢复跟随语种
- `ConfigProvider` 未显式传 `direction` 时跟随 `LocaleService.getDir()`
- 主题：`packages/theme/styles/rtl.scss` + chrome 逻辑属性（`border-inline-end` / `margin-inline-start` / `text-align: start`）

## 2. 目录

```
packages/locale/
├── I18N.md
├── index.ts
├── keys.ts                 # LocaleKeys 便捷命名空间（叶子必须 ∈ LocaleKey）
├── message-schema.ts       # 自动生成：LocaleKey + LocaleMessages
├── messages.ts             # LocaleCode + locales + LOCALE_META + registerLocale
├── LocaleService.ts
├── zh-CN/ … ru-RU/         # LTR 产品语种
└── ar-SA/                  # 内置 RTL（独立阿语包；exampleDoc 持续阿语化）
```

新增语言：复制现有目录 → `messages.ts` 注册 → **全部 key**（`satisfies LocaleMessages`）→ 跑 `extract:i18n`。

| 代码 | 语言 | dir |
|------|------|-----|
| `zh-CN` | 简体中文（默认） | ltr |
| `zh-TW` | 繁體中文 | ltr |
| `en-US` | English | ltr |
| `ja-JP` | 日本語 | ltr |
| `ko-KR` | 한국어 | ltr |
| `ko-KP` | 조선어 | ltr |
| `ru-RU` | Русский | ltr |
| `ar-SA` | العربية | **rtl** |

`ar-SA` 为核心 UI 域（common / button / tip / error / auth / biz / nav / page / component / industry）全量阿语；`exampleDoc` 以阿语为主，组件专有名词 / 技术栈名（Vue、TypeScript、Avatar…）可保留拉丁词干。

切换：顶栏下拉、`LocaleService.setLocale(code)`、URL `?lang=ar-SA`。  
`toggle()` 按 `LOCALE_CODES` 循环内置语种。  
自定义 / 远程包：`registerLocale(code, messages, meta)`（`meta.dir` 可为 `rtl`）。

## 3. Key 命名

```
{domain}.{entity}.{descriptor}

button.save
page.theme.title
tip.saved
error.network
biz.login.title
auth.login.passwordRequired
```

| 域前缀 | 用途 |
|--------|------|
| `common.*` | 通用词：是/否/加载中/未知 |
| `button.*` | 按钮文案 |
| `page.*` | 页面标题 / 导语 / eyebrow |
| `tip.*` | 成功/信息类轻提示（Toast info/success） |
| `error.*` | 错误 / 失败 / 校验失败 |
| `biz.*` | 五大业务模块（login/users/orders/content/settings） |
| `auth.*` | 登录注册流程 |
| `nav.*` | 侧栏 / 面包屑（与路由 meta.title 可共用 key） |

**规则**

- 全小写 · 点分层 · 英文词干  
- 同一语义全局一个 key（`button.cancel` 不要再拆 `biz.cancel`）  
- 插值：`error.minLength` → `最少 {min} 个字符`，用 `t(key, { min: 6 })`

## 4. 使用方式

```ts
import { useLocale } from '@amg-webui/hooks'
import { LocaleKeys } from '@amg-webui/locale'

const { t, tDyn, dir, setDirection } = useLocale()

t(LocaleKeys.button.save)           // 保存
t(LocaleKeys.error.minLength, { min: 6 })
t('button.save')                    // OK — 字面量 ∈ LocaleKey
// t('not.a.key')                   // 编译失败
tDyn(dynamicKey)                    // 运行时校验
```

模板：

```vue
<Button>{{ t('button.save') }}</Button>
<h1>{{ t('page.theme.title') }}</h1>
```

Toast：

```ts
ToastService.success({ summary: t('tip.saved'), detail: t('tip.changesLive') })
ToastService.error({ summary: t('error.generic'), detail: t('error.network') })
```

路由 `meta.titleKey: 'page.theme.title'`（类型为 `LocaleKey`），壳层 `t(route.meta.titleKey)`。

## 6. LocaleService

- `LocaleService.init()`：读 `localStorage` + URL `?lang=zh-TW` 等  
- `setLocale(code)` → `html[data-locale]` + `lang`/`dir` + 持久化  
- `getDir()` / `setDirection(dir | null)` — RTL 控制  
- `registerLocale(code, messages, meta)` — 自定义 / 远程包  
- 缺省：`zh-CN`  
- `LOCALE_META`：原生显示名 + `lang` + `dir`  

存储键：`amg-webui-locale-v1`。

## 7. Do / Don't

**Do**

- 新文案先加语种文件 → `npm run extract:i18n`（重生 schema）→ 可选补 `LocaleKeys`  
- Play 与 business 组件用 `t()` / `LocaleKeys`  
- 错误与提示用 tip/error，不用 button key  
- RTL：优先 CSS 逻辑属性；需镜像的图标加 `.vp-rtl-mirror`  

**Don't**

- `<Button>保存</Button>` 硬编码  
- 把 Skill Runtime 的开发错误文本直接显示给用户  
- 在 SCSS 写文案  
- 用 `as LocaleMessages` 掩盖缺 key（必须用 `satisfies`）  
- key 用中文或驼峰（`按钮保存` / `btnSave`）

## 8. 复数规则（ICU-lite · 锁定）

数量相关文案 **必须** 用复数段，禁止只写 `{count}` 让俄语/英语变形出错：

```
{count, plural, one {# элемент} few {# элемента} many {# элементов} other {# элемента}}
```

- 实现：`packages/locale/plural.ts`（`resolvePlurals`），`LocaleService.t()` 内部先做复数选择再做 `{param}` 插值
- 类别选择走 **CLDR / `Intl.PluralRules`**（按 locale 缓存）：`zero | one | two | few | many | other`
- 精确匹配 `=N` 优先于类别（如 `=0 {Нет элементов}`）
- `#` 在分支内代表该数字；分支里仍可引用其他 `{param}`
- `other` **必填**：值缺失 / NaN / 类别缺失时兜底
- 各语言要求：`ru-RU` 必须有 `one/few/many/other`；`en-US` 至少 `one/other`；中日韩无复数变形，保留 `{count}` 直插即可

## 9. 文案长度（中英膨胀 · 禁止误伤 `…`）

中文常 2 字即可（保存 / 取消），英文往往多词（Save / Sign out / Continue editing）。按中文宽度固定布局，英文会被 `text-overflow: ellipsis` 截成 `…`。

### 原则

| 文案类型 | 策略 |
|----------|------|
| 按钮 / 导航 / Tab / 页面标题 / 退出等 **UI 文案** | **优先撑开或换行**；最多 2 行 clamp，不要单行强制 `…` |
| 用户名、ID、长路径等 **动态数据** | 允许 ellipsis，**必须**配 `:title` / tooltip |
| 表格表头 | 允许换行；单元格数据可 nowrap + ellipsis |

### 实现入口

- `packages/theme/styles/i18n-layout.scss`（已 `@import` 进主题）
- `html[data-locale='en-US'|'ru-RU'|'ar-SA']` 加宽侧栏/Tab；`ja-JP` / `ko-*` 轻度加宽  
- 工具类：`.i18n-label` / `.i18n-btn-label`（可 wrap）· `.i18n-truncate`（故意截断）· `.i18n-clamp-2`
- Button：`overflow: visible`，宽度随文案；极窄处用 `.p-button-wrap`

## 10. 变更流程

1. 在 **全部** locale 域文件写入文案（含 `ar-SA` 若非 re-export）  
2. `npm run extract:i18n` — 对齐校验 + 重生 `message-schema.ts`  
3. 可选：`keys.ts` 增加 `LocaleKeys` 常量（必须已是 `LocaleKey`）  
4. 组件改为 `t(LocaleKeys.…)` 或 `t('literal.key')`  
5. 核对长文案语言（en / ru / ja / ko / ar）是否被 `…` 截断  
6. RTL：用 `?lang=ar-SA` 或 i18n 页强制 RTL 预览壳层镜像  
7. 必要时更新本文与 Cursor rule
